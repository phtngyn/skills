# Prompting pstack

State the outcome, scope, meaningful constraints, and observable completion condition. Include the relevant branch, bug reproduction, or source artifact. Let the workflow choose implementation details.

Use `$poteto-mode` for execution, `$architect` for a design before implementation, or `$how` and `$why` for explanation. Say "with checkpoint" when the design must be reviewed before code. Say "plan only" when implementation is not requested.

For long work, name the terminal condition and any limits. A request to keep working does not automatically authorize external publication, merging, deployment, or a future schedule.

Steer with concrete evidence: "show the actual stored value", "compare the old and new behavior", "apply subtract before you add", or "explain which assumption failed".
